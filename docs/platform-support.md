# 平台支持与验收

日期：2026-10-12（Asia/Shanghai）。

Linux 与 macOS 共用页面和 IPC，分别适配包管理器、目录和启动机制。Windows 只规划。

## 本次实施

- 参考 Lemon Cleaner 统一主窗口、清理结果及工具页面，采用白色背景、绿色操作、橙色统计；清理结果可展开文件名、路径、大小并查看文件位置。
- 系统规则和容器垃圾纳入垃圾扫描，使用同一个选择列表和清理按钮。移除独立的系统诊断/空间占用检查列表；目录分析仅保留逐层占用功能。
- Linux APT、journal、tmpfiles 通过专用管理助手扫描和执行固定命令；显示候选文件及大小，未知显示失败。Docker 显示本地守护进程可回收估算，不包含数据卷，选中后执行对应 prune。
- 清理页支持主动管理员授权。Linux 打包独立助手，系统认证安装/更新与短期会话授权；macOS 打开隐私设置。授权失效重新认证，不保存密码。
- 开发者垃圾包括声明式工具缓存规则与手动指定项目目录的深度扫描，保留天数可调，默认不勾选，清理前核对元数据、年龄和可见进程路径。
- 应用卸载列表显示 Linux 本地图标或 macOS 应用包图标，缺失/加载失败时显示统一占位图标。
- 脚本适配 Linux / macOS 安装与构建，CI 配置两个平台的原生检查；未添加 Windows 实现。

## 本机证据

- Debian 13 x86_64，WebKitGTK 4.1 可用。
- Vue TypeScript 检查和 Vite 生产构建通过。使用项目本地 CLI，因为全局 pnpm 启动器引用的缓存文件失效；未改动全局工具配置。
- 主程序严格 Clippy 与 17 项测试通过，独立助手严格 Clippy 与 4 项测试通过。覆盖清理范围/符号链接、重复文件保留副本、开发产物识别/保留时间/扫描后变化、journal 活动文件保护、tmpfiles 候选解析、Docker 共享层统计及不清理数据卷、包参数约束。Linux 测试额外编译 macOS 适配模块并校验 Homebrew/launchctl 解析，不等于 Mac 原生验收。
- 最新只读实测：196 个应用、196 项图标数据，145 个菜单条目、42 个启动项、12 个目录分析入口；`df` 和目录 `du` 成功。垃圾扫描返回 5 类，系统扫描因助手安全校验未通过而显示未完成；未将其作为已授权系统扫描成功。数量仅为当次机器快照。
- 浏览器此前检查过 1000×650 主窗口及清理结果布局、文件详情，使用带标识的测试数据，不执行真实清理。最新应用图标、深度扫描入口修改时浏览器已断开，尚未完成最终视觉复核。
- Linux 发布版 `tauri build --no-bundle` 通过，产物为 `src-tauri/target/release/tauri-app`。未把无安装包构建视为 DEB/RPM/AppImage 打包验收。
- 脚本语法、Polkit XML 和差异空白检查通过。

## 待真实环境验收

- macOS Intel/Apple Silicon 原生编译、APP/DMG、签名、公证、Finder/TCC、Homebrew、LaunchAgent 与 ICNS 图标转换；本机不是 Mac。
- Linux 各发行版安装包、认证代理、首次助手安装/更新、授权取消/过期、实际系统和 Docker 清理。代理未执行真实卸载、更新、root 授权安装或系统清理。
- 实际数据量下的开发者扫描性能、文件访问时间行为、退出开发工具后的清理与重新构建、废纸篓恢复和部分失败提示。
